# Store/Wheel 完整补拍回归 (2026-09-17)

维护者授权运行 Store、TTL、故障注入、Wheel、零分配五组组件测试. 本次测试的是 `179f316` 之后的工作区修复: `void Store::tick(now)` 一次补齐经过的完整拍, Store 使用 `Wheel<4, 10>` 和默认 10ms 精度.

提交前补记: 测试完成后, 维护者将 `store.hpp` 和 `store.cpp` 中的 `tick_time_` 统一重命名为 `clock_`. 已与测试时归档逐字核对, 除该名称替换外没有其他差异; 重命名后未重新构建或测试. JSON 中的源码摘要保留实际测试版本.

复用 Ubuntu Linux x86_64 的项目内 GCC 16.2.0 和现有四套 CMake 缓存. 每次只构建五个组件目标, 单任务编译和测试, 没有下载工具或依赖. 测试期间没有发现需要继续修改源码的问题.

## 已验证的行为

- 超过原 1024 拍预算后仍在一次调用中完成到期删除, 跨多个截止的删除只产生一个提交批次.
- 模拟一小时没有驱动后完成补拍; 补拍前、补拍后写入的五秒绝对租约在同一截止失效, 不提前删除或额外延期.
- 不足一拍保留, 重复或倒退时间不产生额外提交; 续租、取消、永不过期、扩容、删除重建及并发快照继续通过.
- 全有符号时钟范围的极值用例使用大间隔, 一次调用仅推进两拍, 不遍历 UINT64_MAX 拍.
- 历史空闲淘汰、零/负 retention、失效快照释放及外部旧快照持有行为通过.
- 每个配置通过 174 个写入和 7 个读取分配失败点; 包含多拍收集、提交失败后的下一拍重试, 检查不丢失、不重复删除.
- 每个配置执行 Store 三个固定种子的 6000 步模型操作, Wheel 八个配置/起点组合的 240000 步随机模型操作, 另有边界、排空和生命周期检查.
- `Wheel<4, 10>` 覆盖 1024 槽边界、第三层节点实际下沉、高位边界、整数回绕、最大延迟调度与取消.

两种时间轮的独立分配检查均覆盖构造、调度、取消、回调内重排、未到期节点的析构清理:

| Linux x64 实例 | 测量区间堆分配 | 回调次数 | Node 大小 | Wheel 大小 |
| --- | ---: | ---: | ---: | ---: |
| `Wheel<5, 8>` | 0 | 2048 | 24B | 10264B |
| `Wheel<4, 10>` | 0 | 2048 | 24B | 32792B |

这些大小是本平台的实测对象大小. 零分配结论针对上述轮操作及不分配的回调, 不适用于 Store 的整个写入或到期批次提交.
