# 连续纪元时钟与单时间轴 TTL

状态: 2026-09-18 已迁移实现; 500 ms 门槛的 Debug/Release 均通过完整 21 项 CTest, 包括真实时源进程场景.
固定 Unix 纪元起点为 1970-01-01, 单位为纳秒; 运行中单调前进, 参考源变化不改变 Store 坐标.
当前实现和部署边界见 [Pulsar 与 Star 对时](design.md), 当前结果见 [500 ms 回归](regression-20260918-500ms.md).
此前 Sanitizer 和 200 ms 真实时源失败记录保留在 [历史回归报告](regression-20260918.md), 不算作新门槛的重复执行.

## 1. 核心契约

每个进程拥有一个 EpochClock. 数据、Store 和 Wheel 只认识它输出的纪元时间:

```text
本地经过时间 + 对时样本 -> EpochClock -> EpochClock::Time -> Store -> Wheel
                              |
                              +-> 时钟质量与诊断
```

- EpochClock::Time 的起点、单位和含义不随 Pulsar/Star 启动或连接变化而改变.
- 对一个运行中的 EpochClock, 非重叠读取单调不减, 正常经过时间会推动它继续前进.
  时钟分辨率允许相邻读数相同, 不要求每次读取人为加 1 ns.
- 初始化并公开时间后, 不直接替换时间值或原点. 正负校正通过限速调整吸收, 不回拨、不停走、不跳跃校时.
- 数据项仅持有一个可选的纪元截止时间. 时钟校正、重新采样和参考源重启不改写已有截止.
- 时间轮不感知采样源、连接代次或校准状态, 只按同一条时间轴推进.
- 单调性不等于准确性. 不承诺不同 Star 同一纳秒到期、全局线性一致的 now(), 或零误差的真实时间.

同一 Galaxy 的 Star 必须使用同一个时间尺度. 固定 Unix 起点解决数值含义,
采样和质量门槛解决误差; 不能让每台 Star 自选任意偏移后仅凭“各自单调”互换截止时间.

## 2. 类型与所有权

以下接口已落到源码并执行功能回归, 性能仍待单独测量:

| 类型/字段 | 含义 |
| --- | --- |
| `EpochClock::Time` | 强类型的非负 int64 纳秒数, 同一固定 Unix 起点; 不隐式接受 steady_clock::time_point |
| `optional<EpochClock::Time> deadline` | 唯一业务期限; 空表示无限期, 不以 0、负值或最大整数编码无限期 |
| `EpochClock::Reading` | 成对返回当前时间、误差估计和是否可接受新有限期限; 不进入每条数据 |
| EpochClock 内部状态 | 本地采样锚点、纪元值、待消化偏差、舍入余数、最后有效观测及质量信息 |
| Store 推进位置 | 时间轮已经处理到的纪元拍边界; 这是处理水位, 不是第二种时间参考系 |
| Wheel 节点 | 原有侵入式链接和到期拍索引; 不额外保存本地绝对截止 |

Entry 和 Delta 不保存 `era` 或重复的本地 `expire`.
未来同步快照和持久记录必须保存同一个 deadline, 不能只保存 Value 或剩余 TTL 后在恢复时续满.
Snapshot 已同时保存 value/deadline, 业务持久化和网络恢复仍未实现,
不能将元数据齐全等同于完整业务恢复服务.

RPC 超时、重试退避、历史保留期和性能测量仍使用各自的本地经过时间.
这些设施不改用可能有调速误差的业务时间, 也不把本地期限放回业务数据.
现有 `Clock = steady_clock` 不全局替换, 避免改变准入、gRPC 关闭和旧夹具的语义.

## 3. 底层计时和公共时间起点

生产目标仍为 Linux. EpochClock 的经过时间使用 CLOCK_BOOTTIME,
使内核计入系统 suspend 的时长; 本地采样锚点也使用同一来源.
它不受墙钟 step 直接影响, 但仍依赖内核和虚拟化平台正确计时, 不是独立硬件计时器.
相关边界见 [Linux clock_gettime](https://man7.org/linux/man-pages/man3/clock_gettime.3.html).

本地经过时间从不直接作为业务时间发到其他 Star. 冷启动前先建立公共纪元锚点,
运行期间才用本地增量继续推进. 精度探测应测实际采用的经过时间来源, 不测另一只时钟后冒充它的精度.
宿主机/虚拟机暂停后需要重新评估样本年龄和误差, 不能因线程刚恢复运行就把旧样本视为新样本.

固定 Unix 起点是一种坐标约定, 不表示直接把 system_clock::now() 交给 Store.
运行中的墙钟回拨、闰秒处理或 NTP step 都只能成为时钟层的校正输入.
首版沿用宿主机提供的 POSIX/Unix 时间尺度, 不额外实现 TAI 或另一套 leap smear;
Pulsar 的宿主机应采用一致的系统对时策略, Star 不独立混用不同的墙钟尺度.

## 4. 单调推进和限速校正

初始化仅发生一次: 在尚未公开业务时间、尚未处理持久化期限时, 用有效样本建立锚点.
后续 observe() 只能更新目标偏差和质量, 不直接跳到新的时间读数.

每次读取或接收样本先补齐本地经过时间. 简化后的推进公式为:

```text
d = 当前本地经过时间 - 上次锚点
budget = d * slew_ppm / 1_000_000, 保留整数舍入余数
correction = clamp(待消化偏差, -budget, +budget)
epoch_now += d + correction
待消化偏差 -= correction
```

slew_ppm 必须小于 1_000_000, 保证向后修正也不会停止正常走时.
偏差消化完成后恢复正常速率, 不储存空闲时未使用的校正额度以便日后突然跳时.
频繁读取应与一次等量经过时间的推进保持相同结果; 必须保留小数余量, 不让高调用频率吃掉校正预算.
乘法与差值采用足够宽的中间类型并检查边界, 不用可能溢出的 int64 乘法或静默饱和冻结时间.

新样本对应本地接收时刻 B, 发布样本时在锁内取得当前经过时间 C, 先把现有模型推进到 C.
将样本的目标纪元值按 C - B 外推到 C, 并把这段年龄的误差计入质量, 再计算“目标纪元值 - 当前输出”.
它替换旧的残余偏差估计, 不把每批重复看到的同一误差不断累加.
样本顺序与最后接受的观测比较, 不与最近一次 read() 比较: 并发读取已经推进过 B 不代表样本无效.
超过有效年龄、相对上次观测反序的样本和停止后的 RPC 完成结果不修改模型.

首版采用一个短锁保护该模型, 读取不分配、不写盘、不调用 Store 或 RPC.
不先引入无锁高水位、每 CPU 时钟或多套校正控制器. 这是进程级固定成本,
Store 每轮/批读取一次, 不在到期循环中为每个 Key 重新采样时钟.

限速调整参考 [RFC 5905 的 Clock-Adjust Process](https://www.rfc-editor.org/rfc/rfc5905.html#section-12),
但这里只实现项目需要的时间模型, 不声称实现完整 NTPv4 时钟驯服算法或修改宿主系统时间.

### 首版内部参数

这些已作为内部默认值实现, 不写入业务协议, 仍需后续测试验证:

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 最大调速 | Pulsar 正负 500 ppm, Star 正负 1000 ppm | 为 Star 跟踪上游调速保留余量, 不包含底层误差 |
| 新样本保鲜期 | 5 s | 延续现有采样策略, 用本地经过时间计算 |
| 新有限期限最大误差估计 | 500 ms | 同时考虑上游误差、网络、未消化偏差和样本年龄; 2026-09-18 经用户确认由 200 ms 放宽 |
| 单批采样 | 8 次, 至少 3 个有效 | 延续现有完整 RPC 批次条件和异常过滤 |
| RTT/处理时长边界 | 200 ms | 保留现有边界, 重新推导调速下的漂移容差 |
| Store 拍间隔 | 10 ms | 延续既有默认值, 不以限制补拍次数截断追赶 |

500 ppm 下, 10 ms 偏差约需 20 s 消化, 1 s 偏差约需 2000 s, 均忽略新的观测与底层漂移.
这是不跳时的明确代价. 10 s 的业务时长也不再承诺恰好等于 10 s 本地经过时间;
Pulsar 仅调速一项的名义偏差约为 5 ms, Star 的 1000 ppm 对应约 10 ms. 不通过重写每条 deadline 来抵消它.

## 5. 质量与失联

EpochClock 初始化后, 时间值的可用性与“可以接受新有限期限”分开表示:

| 情况 | 已有数据/时间轮 | 新有限期限 |
| --- | --- | --- |
| 尚未初始化 | 等待共同纪元锚点; 不猜测有限截止是否到期 | 拒绝 |
| 新鲜且误差达标 | 正常推进 | 接受 |
| 失联、样本超时或误差超限 | 继续按本地经过时间走时和到期 | 拒绝, 返回时钟未就绪 |
| 恢复采样 | 不倒退、不清零, 限速消化偏差 | 质量恢复后接受 |
| 本地计时反序/算术耗尽 | 明确报告计时设施故障, 不伪造可靠时间 | 拒绝 |

无期限数据、显式删除和连接管理不因单纯对时失效而被停止.
Pulsar 重启不会续满 TTL: deadline 不变, 运行中的 Star 持续走过断线时段.
已经到期并删除的数据不会因后续负校正复活.

误差估计至少包括上游时间误差、四时间戳网络估计、双方精度、剩余校正偏差以及年龄漂移.
不能在新包到来时清零本机尚未消化的偏差, 或把 precision_ns 当成绝对时间准确度.
滤波使用的频率差预算必须计入服务端调速, 不机械复用旧的 500 ppm 公式.
暂按每端底层 500 ppm 的假设时, 服务端另有 500 ppm 调速, raw-client/adjusted-server 的相对预算需覆盖 1500 ppm.
这些是假设下的估计, 不是网络不对称或损坏硬件下的精度保证.

观测年龄采用 2000 ppm 保守误差预算.
失联期间继续消化已经接受的有限偏差, 消化完按正常速率走时.
质量持续恶化要报警, 但不增加“冻结所有 TTL”或“为已有条目再发一个完整 TTL”的降级路径.

## 6. Pulsar 起点和重启恢复

### 6.1 可信时间来源

Pulsar 的固定纪元锚点来自已受系统对时服务管理的宿主机时间. Astra 只读取时间和可用的同步/误差信息,
不负责安装、启动或修改 chrony/ntpd/systemd-timesyncd, 不新增独立 UDP NTP 服务.
Linux 可通过只读的 adjtimex 查询检查未同步/错误状态与误差信息,
但这些状态不是对实际物理准确度的证明; 可信系统对时仍是部署前提.
接口边界见 [Linux adjtimex](https://man7.org/linux/man-pages/man2/adjtimex.2.html).

Pulsar 的 EpochClock 也经本地经过时间推进, 墙钟变化经过同样的限速和质量处理.
Star 只向当前授权的 Pulsar 采样, 不用自己的 system_clock 绕过上游校准.
外部时间源不可用时, 已运行实例继续 holdover; 没有锚点的冷启动不能凭空恢复断电时长.

### 6.2 Pulsar 重启与单调性的边界

单调保证属于一个持续运行的 EpochClock. Pulsar 重启后从可信公共时间重新建立锚点,
其新估计可能略早于停机前的旧估计; 运行中的 Star 将它作为校正输入, 不直接替换自己的时间.
因此参考源重启不需要重置 Store/Wheel, 不需要给数据附加 era.

首版不增加时钟专用日志、持久输出上界或重启等待窗口. 这些机制解决的是
“任意崩溃前后所有已发出的读数绝不反序”, 比本轮运行中业务时间连续的要求更强.
固定 Unix 起点不自动提供该保证, 文档和接口也不承诺它.
未来恢复持久业务状态所需的已提交时间水位属于检查点契约, 不成为每条数据的第二种期限.
跨 Star 的读数仍有误差, 时间不能替代业务版本或共识协议.

### 6.3 Star 和整群重启

Star 新进程先校准公共时间, 再装载/开放有期限的业务状态. 若未来检查点含已提交的时间水位,
恢复值不得退到该水位之前; 未达到条件时保持恢复未就绪, 不把旧截止平移或改成 now + 原 TTL.
恢复时直接比较绝对 deadline: 已经过期的条目先清理, 未来条目重新入轮.

全群断电后, 没有可信外部时间或可靠硬件计时就无法知道离线时长.
该情况下不承诺自动恢复有限租约服务. 持久化一个时间数值只保存过去, 不能测量断电期间经过了多久.
虚拟机快照回滚也不等于正常重启; 不把回滚后的本地时钟/状态当成跨历史单调性的证明.

## 7. Store 和 Wheel 的流程

### 初始化

首次取得有效 EpochClock::Time 时建立 Store 拍边界. 若存在恢复数据, 按当前时间安排期限,
不从 1970 年开始逐拍追赶. Wheel 可保持从零开始的内部拍索引, Store 只记录与其对应的纪元边界.
Wheel 本身的侵入式链接、分层、取消和超长期限分段唤醒规则不改变.

### 正常一轮

```text
EpochClock 补齐本地经过时间, 得到一个稳定的 EpochClock::Reading
    -> Store.tick(epoch_now)
    -> 按拍触发、核对 deadline 并准备完整到期批次
    -> 提交数据、历史、快照索引和版本
    -> 处理本批新增/续租
```

Store 在锁内只使用本轮捕获的时间, 不在每个节点回调时重新读钟.
`pending = floor((epoch_now - 已推进边界) / interval)`; 每完成一拍才推进处理水位.
小于一拍的余数保留, 不通过每次直接覆盖水位累积精度损失.
若输入时间早于已处理水位, 不回退或重复执行; 上层应检查过期的批时间或调用顺序.

新增/续租将相对 TTL 在入口转换成一次绝对 deadline, Store 只存绝对值.
原有单独调用 put 的路径按 `ceil((deadline - 已推进边界) / interval)` 安排槽位,
因此即使批间仍有排队延迟, 也不把延迟再加到 deadline 上.
不能用 `deadline - 当前时间` 直接相对一个尚未推进的旧轮入槽.

维护与写入保持两个可观察提交边界. 不在 put 内暗中提交过期删除后,
又把本次写入的 bad_alloc 描述成“整个 Store 没有变化”.
推荐控制循环先 tick 再处理一批写入; 不要求每个 put 单独进行全量补拍.
已过期的输入沿用内部 Store 的现有规则: 入轮最早下一拍处理, 不在 put 内调用过期回调;
将来业务 RPC 如需拒绝超时请求, 在其契约中单独定义, 不靠时钟迁移偷偷改变写入语义.

回调只比较 deadline 与当前处理拍边界, 未到期则重新入轮. 不判断 era、参考源或第二份本地期限.
源切换和普通校正不扫描全表, 不重置时间轮, 不更新业务版本.
分配失败沿用既有批次原子性与节点重排, 处理水位和实际完成的拍保持一致.
不恢复 max_ticks; 大跨度推进的成本和批量到期成本仍需单独测量, 单时间轴不能使它们自动成为 O(1).

## 8. gRPC 对时协议调整

保留 TLS、凭证、Callback API、独立资源预算和 gRPC 四时间戳算法.
数据不附带来源纪元. Pulse 不新增每 Key 时钟票据或签名域.

| 字段/行为 | 目标语义 |
| --- | --- |
| Ping.t0 / Pong.t0 | Star 本地经过时间纳秒, 仅用于匹配与测量, 不作为业务时间 |
| Pong.t1 / Pong.t2 | Pulsar 连续公共纪元时间, T2 不早于 T1 |
| Pong.era, tag 4 | 删除并 reserved 编号与名称, 不复用为另一个含义 |
| Pong.precision_ns, tag 5 | 保留, 描述实际读钟精度, 不表示到固定 Unix 时间的准确度 |
| Pong.uncertainty_ns, tag 6 | 当前上游误差估计, 纳秒; 客户端还要加入自身网络与校正误差 |
| Pong.synchronized, tag 7 | 上游是否已初始化且质量达标; 缺省 false, 不把缺字段当作可信时间 |

滤波继续根据 T0/T3 本地经过时间和 T1/T2 公共时间计算偏移及 delay,
所得偏移只作为 EpochClock 的目标观测, 不直接覆盖对业务公开的时钟.
时间服务未就绪时, RPC 返回 UNAVAILABLE, 不发送看似有效的零时间.
单批只使用本条 RPC 的有效响应. 单个采样线程串行处理完成, 停止后不发布迟到结果;
更换连接可清空滤波样本, 不清空 EpochClock 已经建立的锚点.

本项目实现阶段不做旧语义兼容: 更新 proto、生成源码、Pulsar、Star 和测试须在同一迁移中完成.
不能仅因字段类型仍为 uint64 就混用旧的进程/主机单调时间与新的公共纪元时间.
未来如要求滚动混跑, 再增加明确的协议能力协商, 不在首版保留两套业务时间模式.

## 9. 实施边界和删除清单

| 部分 | 处理 |
| --- | --- |
| common/clock | 将瞬时偏移发布改成连续 EpochClock, 增加独立质量输出和可注入经过时间/参考源 |
| pulse_client / ClockFilter | 保留采样与过滤, 输出目标观测; 删除业务 era 和 reset 后丢失走时锚点的行为 |
| Pulsar Pulse | 改为读取公共 EpochClock, 增加上游质量; 不再按启动生成业务时间纪元 |
| Pulsar 私有状态 | 不增加时钟持久日志或启动代次; 原有成员登记持久化保持其独立职责 |
| Store | 合并为单一期限类型, 删除 global/local 双模式、双期限、lease_time 的换纪元扫描 |
| LeaseClock | 职责移入进程级 EpochClock 后删除, 不改名保留第二层时间映射 |
| SnapshotIndex / Wheel | 保留现有算法, 仅适配单一期限记录和时间类型, 不引入新持久化容器 |
| Runtime | 获取时间并推进 Store, 记录质量变化; 不处理每 Key 的纪元迁移 |
| Go Supervisor / 冻结 SDK | 不机械迁移, 没有同一套 Pulse 时钟; 后续 SDK 协议使用同一 EpochClock::Time 契约 |

本轮实现时钟/协议/Store 迁移, 补齐测试并在用户授权后执行回归. 不实现多 Pulsar 选主、跨 Galaxy 时间桥接、SDK 业务协议或业务数据落盘.
不下载工具/依赖, 不修改系统时钟或系统对时服务, 不触碰 README.
业务时钟的短锁和标量运算不宣称达到某个吞吐值; 须通过当前项目的负载测量确认.
