# Pulsar 500 ms 误差门槛回归

日期: 2026-09-18. 用户明确要求将误差容忍放宽到 500 ms 并进行测试.
环境: Ubuntu 192.168.0.119, Linux x64, 项目内 GCC 16.2.0.

## 变更范围

共用常量 clock_uncertainty_limit_ns 从 200000000 改为 500000000 ns.
Pulsar 系统参考读取、Star 四时间戳过滤、首次初始化和新有限期限资格均沿用该常量.
新增或调整断言覆盖 400 ms 可用、500 ms 边界可用、500 ms + 1 ns 被拒绝,
以及边界观测继续老化后失去资格. 注入物理参考的正常观测使用 400 ms,
验证物理参考层的实际接入, 同时保留正负跳变、失联、恢复和重启测试.

200 ms RTT/处理时长上限、200 ms 精度探测窗口、5 s 样本新鲜度及调速参数保持原值.
不修改宿主 NTP 配置或系统时间, 不下载工具/依赖.

## 本轮验证

Debug 和 Release 分别增量构建并运行完整 21 项 CTest, 包括 Store、时钟、
Pulsar 成员表、真实 TLS/RPC、Python 夹具和 Pulsar + 两台 Star 的进程场景.
进程场景使用当前宿主真实时间质量, 检查互联、失联续走、重新就绪及正常退出.
失联与恢复均只接受当前阶段的新日志, 不复用旧质量事件.

| Debug | 通过, 159.022 s | 21/21 通过, 69.00 s |

Debug 真实进程场景通过, 耗时 10.29 s. CTest 前后只读采样的内核 maxerror
分别为 115452 us 和 149952 us; 注入参考用例另外验证了高于旧门槛的 400 ms 观测.
Release 真实进程场景通过, 耗时 12.42 s; CTest 前后的 maxerror 分别为 163595 us 和 128244 us.
两种配置均首次通过, 没有对失败场景重复执行. 源码格式与 diff 空白检查通过.
结束后没有遗留测试服务进程或 Pulsar 临时目录. 清理记录与 12 个二进制摘要保存在
build/testkit/results/pulsar-500ms-cleanup-20260918.json.

本轮未重复 ASan/UBSan、TSan、额外拓扑故障矩阵或长期负载测试.
[200 ms 历史回归](regression-20260918.md) 的 Sanitizer 结果只对应当时源码和门槛,
不冒充本轮 500 ms 产物的执行结果. 用例数不是行/分支覆盖率.
