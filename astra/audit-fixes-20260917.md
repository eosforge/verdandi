## 已实施

- Store 的空闲 tick 也执行历史时间淘汰, 不再要求写入或 TTL 删除才能触发维护. retention=0 表示不保留历史, 负值在构造时拒绝. 正常时间淘汰在 age >= retention 时生效, 先判断时刻顺序再计算无符号距离, 避免极值相减溢出.
- Store 每次成功修改后解除内部对失效快照的强引用. 临时持有者先于状态锁声明, 最终析构发生在解锁之后; 已交给外部读者的快照继续有效. 失败或无修改的操作保留原缓存.
- 全部 51 个 Proto Mutator setter 按值返回仅持有消息引用的代理. 保留链式调用, 消除保存临时代理返回引用的悬垂路径, 不复制底层 Protobuf 消息.
- tick 按调用预算推进, 使用已有 tick_time_ 保存实际进度, 不新增目标代次、后台线程或另一个待追赶队列. Wheel 本身不改动.

## tick 的当前语义

```cpp
std::uint64_t tick(Clock::time_point now = Clock::now(), std::uint64_t max_ticks = 1024);
```

- max_ticks 必须为正, 默认每次最多推进 1024 个完整逻辑拍; 可由调用方调整.
- 默认 1ms 间隔下, 单次最多追赶 1.024 秒的逻辑时间. 这不是执行耗时, 也不是经基准证明的最佳参数.
- 返回值为距离本次 now 尚余的完整拍数, 不足一拍的余量继续保留. 返回 0 表示已经处理完可推进的整拍.
- 相同 now 可重复传入并逐次追平. 相对于已推进时刻的倒退输入不倒拨时钟. 每次计算目标和预算一次, 不在每个空拍重新除法计算差值.
- 有剩余时, 调用方应在后续调度继续调用. 不在 Store 内连续循环直到清空 backlog, 否则无法达到单次让出锁的目的. 当前生产 Runtime 尚未实例化 Store, 没有需同时调整的业务驱动.
- 每次调用中实际收集的到期项仍作为一个原子批次提交. 同一次大跨度追赶拆为多个调用时, 可以产生多个批次, 调用之间允许读写和续租.
- 数据、历史和版本在分配失败时不部分提交. 时间轮可能已推进, 被摘节点继续按原有规则重排, 下次调用重新计算剩余拍数.
- 历史维护使用传入 now, 不使用尚在追赶中的 tick_time_, 因而不会等待旧时间轮追平才清理过期历史. 历史批次的生成时间仍来自实际单调时钟, 未改变写入接口或增加测试专用时钟回调.

预算只限制 Wheel::tick 的调用次数. 一个拍中可能有很多节点, 历史淘汰和单批提交也仍可能耗时. 尚未追平期间, 有限 TTL 条目可能仍等待清理; 返回非零不能被上层解释为当前时间的到期处理已完成. 不据此宣称固定持锁时长或硬实时响应.

原有 tick/README 说明尚未同步改写, 以本次函数签名及本记录说明此次行为变化; 后续统一注释时应一并更新.

## 保留的边界

- 历史批次数仍不是内存字节预算. 业务输入大小、网络单次响应、慢订阅者资源限制尚无对应服务实现, 本轮不把这些未来边界硬塞进内部 Store.
- 低频控制会话保持现有 Runtime 组织; 不新增就绪队列、无锁容器或每 Key 锁. Planet 业务继续暂停.
- 未修改 README 或旧设计文档的方向冲突, 未统一改写源码注释.
- Store 长 TTL 的完整分段唤醒和 TTL 争用 p99 仍需专门的验证设计; 本轮不以近端边界用例替代它们, 不启动超长逐拍遍历.
