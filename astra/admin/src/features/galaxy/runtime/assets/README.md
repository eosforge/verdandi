# Celestial Model Assets

[English](README.md) | [简体中文](README_CN.md)

These models are originally generated by `admin/scripts/build-celestial-models.mjs` and use the repository MIT license.
All three GLBs contain real triangle meshes, without image planes, external URIs, texture downloads, compression decoders, or third-party assets.
The standalone pulsar adds no GLB: `../pulsar/createPulsar.ts` builds a spherical core, closed beam volumes, and magnetic tubes, using real 3D meshes and scene-scoped resources.

| File | Content | Runtime use |
| --- | --- | --- |
| star.glb | Uneven Surface sphere and spherical Corona shell | Available Stars share geometry with separate coloring |
| planet.glb | Simplified rocky Surface sphere | Planet instances share geometry/materials |
| black-hole.glb | Core shadow proxy, Horizon optical shell, continuous Disc and ellipsoidal Glow under Accretion | Stars in black-hole state |

Reproduce in `admin/` with existing Node.js and Three.js:

```text
node scripts/build-celestial-models.mjs
```

The script exports only these three local files, without installation/network access. Format generator edits before generating; do not edit binary assets directly.
GLBs contain geometry, vertex colors, transparency gradients, and node names. Runtime replaces star surfaces, coronas, and black-hole volumes with procedural materials.

Black-hole structure references [NASA visualization](https://www.nasa.gov/universe/nasa-visualization-shows-a-black-holes-warped-world/).
The optical shell jointly computes direct/orbiting disk images and capture shadows. It is not a physical event-horizon surface; upper/lower bands are not fixed vertical meshes.
The core has 128×96 segments; disk 256×40. Optical-shell radius is 30; ray-orbit impact parameters cover 0.02..28.
Disk inner radius is `3 rs`, about 5.196; outer radius 24, fading from 19.5. Maximum elliptical half-thickness is 0.28, matching near-edge-on foreground volume samples.
At runtime Core serves picking only; Disc/Glow retain offline structure without duplicate rasterization. A normal sphere does not substitute for the optical shadow.
At the maintainer's choice, weak spherical shading/rim light gives the central shadow depth, changes with viewpoint, and is occluded by foreground disk images. This stylistic effect does not mean a luminous event horizon and adds neither GLB changes nor a separate core draw.

All disk images share one flow texture, emission function, and differential flow field. Model orientation is fixed; flow data is generated locally at runtime without external images.
A periodic 2D density field is baked at initialization, avoiding concentric bands from repeated 1D radial noise; bright knots move/fade on the instance clock.
Flow R stores near filaments, G temperature clouds, B distant segmented clumps, sharing the existing RGBA8 texture/sampling.
Distant clumps select density peaks and add angular gaps/fine-layer perturbations while retaining filtered R-channel energy, blending continuously by projected detail.
Shading uses enhanced warm-white hot emission and low-saturation amber edges. Colors and the threefold display clock do not modify GLBs.
Bind instance time/local camera before drawing; scene materials/textures remain shared.

Orbit precomputation references [Bruneton 2020](https://ebruneton.github.io/black_hole_shader/paper.pdf); equation integration/shading are independently implemented here.
RK4 tables cover captured/escaping rays; invert orbits for finite-distance phase/secondary-image ranges, supporting near views and subpixel coverage filtering.
Distant broad arcs retain actual disk radii, thermal gradients, and edges; whole-node LOD does not replace their shape.
No third-party shader code was copied/downloaded. Volumes are visible from inside/outside without duplicated two-sided surfaces; there are no separate luminous coils or fullscreen Bloom.
Ray angular momentum/circular-orbit frequency determine motion and gravitational shift; both intersections share emission, and narrow images use precomputed radial emission integrals for energy correction.

These remain stylized real-time models. Critical shadow impact parameter is 4.5; disk radius and screen impact parameter differ.
Emission, display gamut, and animation time are artistically adjusted. Curved images use a thin disk/first two intersections; finite thickness supplements near-edge-on foreground only, not full volumetric radiative transfer.
Virtual depth is written near the node, without intersecting other bodies along curved rays.
Background lensing approximates screen-space color/depth, lacking offscreen/occluded information. Full Kerr tracing, physical steady accretion, and complete environmental ray tracing are not implemented.
Reviewed art assets may replace modeling/loading later while preserving node-name contracts and planet instancing.

`celestialAssets.ts` loads/validates models before creating the WebGL canvas. Scene scopes release all GPU resources.
Production Vite builds bundle/content-hash assets automatically; no manual public-directory copying is required.
