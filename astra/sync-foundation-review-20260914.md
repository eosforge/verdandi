# Store 整理说明

状态: 维护者恢复测试后, 已于 2026-09-15 完成本轮完整验证, 全部通过.
基线: `2bf279f`. 本轮不创建提交或推送.

## 本轮改动

- `Store` 将当前值, 完整批次历史和快照缓存保持在同一个所有者中.
- `Entry` 和 `Batch` 收入私有区域, 对外只暴露查询结果和只读快照.
- 写入先准备历史所需分配, 新 Map 项在失败时回滚. 删除和过期不再使用无作用的捕获后重抛.
- 过期清理先收集整批 Key, 历史成功追加后再提交删除, 避免一边收集一边修改状态.
- 版本耗尽时抛错, 不允许提交游标回绕. 缓存未更新时继续保留先前的只读快照.
- 注释区分共享 payload 与完整零拷贝, 区分本地提交序号与 Catalog 发布者业务版本.
- `<format>` 移到文件顶部, 保留标准库格式化和 Ranges 的直接用法.
- 删除单用途 `HoldGuard` 包装, 在控制循环停止操作后显式归还 gRPC hold.
- 控制消息队列恢复为四槽. 当前流只有 Hello/Ping/Pong, 不再因为发送拥塞暂停读取 Pong.
  队列超限或截止耗尽时按原有明确错误关闭, 业务流的资源与流控规则另行实施.

## 构建和协议

`star_sync_store` 为独立内部静态库, 不链接 gRPC. 两个存储测试目标也纳入 core-only 模式.
替换型 new 只链接进独立的分配失败测试进程, 不进入 Star, Planet 或其他测试.

使用现有 Ubuntu 项目中的 protoc 36.1 / grpc_cpp_plugin 1.84.0 生成 C++ 协议源码,
替换之前四个 0 字节文件. 使用 Windows 项目已有协议生成器补齐 Go 类型与消息编号.
整理阶段没有编译生成器; 恢复验证后执行了现有生成器的构建、Clippy 和测试.
两个阶段均未下载或安装工具与依赖.

CMake 对每个声明的生成文件同时检查存在性及非空, 避免空文件被误认作已生成.
恢复验证后, Go 与 C++ 的字节级生成一致性检查均已通过.

`SyncTransport` **仍是草案**, 当前服务没有注册这些 RPC, 也没有 SDK 接入.
草案明确游标必须绑定服务端不透明实例 ID 和原订阅范围, 新增 `cursor_prefix` 表达游标原范围.
这些规则尚未在运行时实施. 独立快照流不代表资源隔离, 分块大小不固定为 4 KiB.
快照与增量的完整衔接, 每条 RPC 的准入和订阅生命周期仍需下一阶段设计与实现.

## 已执行的测试覆盖

- 基础写入/删除, 快照同版本复用, 旧快照保持不变, 普通值传递隔离.
- 租约截止相等时到期, 非租约数据保留.
- 历史截断的包含/排除边界, 未来游标, 零历史模式.
- 多 Key 同批删除, 墓碑淘汰后重新登记不会被旧删除影响.
- 并发写入期间, 快照内容与版本始终对应.
- 插入/覆盖/删除/批量过期的分配失败逐点注入, 在不同 deque 分段位置重复检查.
- 分配失败后的无修改, 无版本推进, 无增量缺口, 异常必须可见.
- 通过后续成功写入强制重建快照, 防止旧缓存遮蔽内部部分修改.
- 控制队列过载的明确关闭及回调排空.

## 完整验证结果 (2026-09-15)

以下结果来自本次重新编译和执行, 不沿用前几轮旧版本的结果.
完整结构化报告及源码哈希见 [验证结果](../testkit/results/cluster-sync-foundation-20260915.json).

| --- | --- | --- | --- |

| Release | 10/10 | 6/6 | 13/13 |

- core-only Debug 的 5 项测试通过. Windows 的 6 项构建入口测试、38 项 Python 框架测试通过.
- 分配失败测试覆盖插入、替换、删除及批量过期, 每次完整遍历实际触发 76 次失败.
- Windows 和 Linux Supervisor 的格式、模块校验、vet、测试、构建通过;
  Linux race 与两项各约 6 秒的 fuzz 通过, 分别执行 8,377 和 29,108 次.
- 两端协议生成器格式、Clippy、4 项测试和生成比较通过. Release 推流基准目标编译通过.
- 4 Star + 2 Planet 的限时验证完成 9 轮故障恢复, 故障阶段 65.555 秒,
  随后稳定运行 15 秒. 进程、监听端口和自有临时目录清理通过.
- 最终对照 198 个验证相关源码文件, 本地与 Ubuntu 测试副本哈希全部一致.

本轮未发现需要修改实现的功能失败. Black 检查发现 `test_processes.py` 和 `test_push.py`
格式不符合现有配置, 已格式化后验证. 生成器输出的末尾空行保持原样, 未手工更改生成文件.

范围为现有骨架与内部存储模块. 服务测试运行于单台 Ubuntu 虚拟机的 loopback,
不能替代真实跨主机网络分区验证. ASan/UBSan 使用已有普通依赖构建,
TSan 使用已有插桩依赖构建. 回归中采样的 RTT 不作为独立吞吐基准.
本轮未启动无限长期测试, 最终检查未发现遗留测试进程. 未提交或推送.

本轮未实施 Catalog 的发布者/CAS 规则, Registry 所属 Star/UUID 规则, 持久存储或复制.
历史限制为批次数, 并非完整内存预算; 接入业务前仍需确定 Key/payload/批次和订阅资源上限.
这些边界不应被当前 `Store` 工具或生成的 RPC 类型掩盖.
