# Catalog 8-hour endurance campaign, 2026-08-27

## Result

The requested continuous eight-hour Catalog qualification is **not complete**
and must not be reported as a pass. The first attempt accumulated 27,907.583
Redis seconds before exposing a WSL-local deadline defect in the test driver.
That defect was corrected and a complete 120-second preflight passed. The clean
rerun then accumulated at least 4,384.824 Redis seconds before it was stopped at
the user's request.

Across the three runs, Redis observed more than nine aggregate hours, but these
were separate intervals and are not equivalent to one continuous qualifying
eight-hour run. No Catalog consistency defect was observed. A later review also
found that both test Subscribers shared the persistent Client and therefore
duplicated synchronous checkpoint writes. The runs remain functional evidence,
but their host-disk pressure is not representative of the corrected test model.

## Attempt 1: rejected clock lifecycle

Evidence:

- [`catalog-soak-8h-redis-clock-20260827.json`](../testkit/results/catalog-soak-8h-redis-clock-20260827.json)
- [`catalog-soak-8h-redis-clock-20260827-samples.jsonl`](../testkit/results/catalog-soak-8h-redis-clock-20260827-samples.jsonl)

The workload used 16 Catalogs, 256 fields of 256 bytes, two Subscribers, and a
128-attempt/s target against an owned Redis 8.8.0 AOF fixture. It reached
27,907.583 Redis seconds, or 96.90% of the required interval, and recorded
3,761,920 attempts. Of these, 3,761,913 were accepted; six stale-version retries
and one transient connection result occurred at deliberate Redis restart
boundaries.

All 73 faults reached before termination passed: 31 script-cache flushes, 15
Pub/Sub disconnects, 15 ordinary command-connection disconnects, eight pauses,
and four AOF restarts. The remaining two scheduled disconnect faults were never
reached. The 931 Redis samples had no sampling failure, eviction, rejected
connection, or blocked client. Stable-window used-memory growth was -42,808
bytes; peak used memory was 7,755,112 bytes and peak RSS was 30,281,728 bytes.

The attempt is rejected because the Go workload ended with `context deadline
exceeded` before Redis `TIME` reached 28,800 seconds. WSL's monotonic clock ran
about 5.56% faster than the Redis qualification clock: the old local
`duration + 10m` context expired after 29,460 Go-test seconds while Redis had
observed only 27,907.583 seconds. Final convergence and language post-checks
therefore did not run.

## Correction and complete preflight

The Catalog load driver now uses a cancel-only parent context; Redis `TIME`
remains the workload and acceptance clock. The outer process timeout now adds a
12.5% clock-skew allowance plus ten minutes for shutdown, giving an eight-hour
run a 33,000-second safety limit.

Evidence:

- [`catalog-soak-clock-fix-preflight-20260827.json`](../testkit/results/catalog-soak-clock-fix-preflight-20260827.json)
- [`catalog-soak-clock-fix-preflight-20260827-samples.jsonl`](../testkit/results/catalog-soak-clock-fix-preflight-20260827-samples.jsonl)

The frozen 72-file fingerprint
`6a5cb5a59b6a251ad5c83b8062e10df8f1cb665651dabc218e38fad3be1f90ec`
passed 121.195 Redis seconds, 16,384/16,384 accepted attempts, and all six short
fault types. The operation mix was 16,000 Patch, 320 Replace, and 64 Delete.
There were no transient results or stale retries. Mutation p50/p95/p99 were
below 2.10/4.20/8.39 ms. Stable-window Redis memory growth was 18,968 bytes,
with no eviction or rejected connection.

Authoritative convergence, final `DBSIZE=0`, the Lua contract, two Rust
`catalog_v2` convergence/checkpoint tests, and six-revision Go/Rust
interoperability all passed.

## Attempt 2: corrected run stopped by request

Evidence:

- [`catalog-soak-8h-redis-clock-20260827-rerun-interrupted-summary.json`](../testkit/results/catalog-soak-8h-redis-clock-20260827-rerun-interrupted-summary.json)
- [`catalog-soak-8h-redis-clock-20260827-rerun-samples.jsonl`](../testkit/results/catalog-soak-8h-redis-clock-20260827-rerun-samples.jsonl)

The same frozen fingerprint remained unchanged through the stop. The last Redis
sample was at 4,384.824 seconds. The last workload heartbeat contained 597,760
attempts and 597,754 accepted mutations. Five stale retries and one transient
result occurred only around the deliberate AOF restart; their counts then
remained fixed. Mutation p95 was below 8.39 ms, peak Go heap was 9,043,544
bytes, and the live goroutine count remained 12.

All ten reached faults passed: four script-cache flushes, two Pub/Sub
disconnects, two ordinary connection disconnects, one pause, and one AOF
restart. Across 147 Redis samples, stable-window used-memory growth was 24,508
bytes, peak used memory was 8,789,000 bytes, peak RSS was 32,198,656 bytes, and
there was no eviction, rejected connection, or blocked client.

Because the run was intentionally interrupted, final authoritative
convergence, Lua/Rust/interoperability post-checks, and final `DBSIZE` were not
run. The outer terminal interrupt also prevented the harness from writing its
normal interrupted summary and completing automatic cleanup. The derived
summary records this explicitly. The owned container and owner-checked data
directory were subsequently removed, and port 36440 was verified closed.

## Final assessment

The corrected harness now defaults to one persistent Subscriber regardless of
fanout; the remaining Subscribers are memory-only. The persisted count is
explicitly configurable from zero through the total fanout. No further long
test was started after this correction, pending review.

| Area | Score | Assessment |
| --- | ---: | --- |
| Lua/Redis contract | 9.8/10 | Atomic bounded glue, strict corruption checks, and repeated recovery evidence; still constrained by one Zone-global revision, Redis runtime failures, and no Cluster support. |
| Go SDK | 9.8/10 | Generic API, immutable lock-free reads, bounded parsing, stable memory, and strong reconnect/restart behavior. The detected defect was in qualification-clock ownership, not Catalog mutation semantics. |

The strongest remaining qualification items are one uninterrupted corrected
eight-hour run, an equal-duration Rust mutation workload, and hard-kill cleanup
supervision outside the test process. None of these observations requires a
Catalog wire-format or Lua semantic change.
