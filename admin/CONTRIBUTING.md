# Admin 贡献与代码规范

本文补充仓库的 [coding.md](../coding.md), 不改变根目录的发布、依赖授权或分支规则.

## 开发流程

1. 使用 `.node-version` 和 `packageManager` 指定的版本. 不自动升级依赖.
2. 先确认具体行为和所属模块, 从最小改动开始, 保留现有交互.
3. 每次源码修改后立即执行所属文件的 Prettier 格式化.
4. 运行 `pnpm check`; 涉及显示或交互时完成 [浏览器验收](docs/verification.md) 中相关项目.
5. 提交说明写清问题、结果、验证与限制; 更新相关架构文档和根目录 `worklog.md`.

依赖下载、安装和升级必须针对具体包取得明确同意, 说明名称、来源、用途和位置.
不得通过 `npx`、临时工具、测试脚本或包管理器的隐式安装绕过授权.
无需额外安装 ESLint、Vitest、路由或状态库即可运行现有检查; 确有需求时再评估和申请.

## TypeScript 与 Vue

- 使用 Composition API、`<script setup lang="ts">` 和显式 props/emits 契约.
- 模块使用具名导出, Vue 单文件组件按约定默认导出. 本地 TypeScript 导入显式写 `.ts`, 兼容 Node.js 原生测试.
- 保持 strict、索引越界检查、可选属性精确检查和可擦除类型语法. 不以 `any`、非空断言或 `@ts-ignore` 掩盖契约问题.
- 数据模型使用只读字段和只读集合. 对外传递稳定 ID, 不用对象引用相等表达实体身份.
- Three.js 对象不进入 Vue 深层响应式系统. 每帧计算留在运行时, Vue 仅接收选择、错误和每秒 FPS.
- 组件名使用 PascalCase, 函数和变量使用 camelCase, 文件按职责命名; composable 使用 `use` 前缀.
- 全局样式仅位于 `app/styles/`; 布局和功能组件使用 scoped 样式, 公共颜色与字体由 CSS 变量管理.
- 当前仅一页, 由 App 装配布局和功能. 增加真实页面后再引入路由; 出现跨功能共享状态后再评估状态库.

## 模块与资源约束

- `model` 不依赖 Vue、Three.js、DOM 或演示数据; `runtime` 不依赖 Vue 或拓扑 API, 资产加载器只读取随应用发布的同源 GLB.
- `ui` 通过 composable 操作场景; 场景只由 composable 动态导入. 跨功能从各自 `index.ts` 进入.
- App 可直接选择演示数据源; 新数据适配器应明确输入校验和转换, 不让网络 DTO 污染渲染代码.
- `pnpm check:boundaries` 用现有 TypeScript 解析器检查这些导入边界. 修改分层时同步更新规则和架构文档.
- 取得 GPU、事件监听、观察器或 RAF 资源后立即登记清理. 初始化失败和正常卸载走同一清理路径.
- `dispose` 必须幂等, 清理一项失败不应阻断其它项. 异步加载必须丢弃已卸载或被替换的旧请求结果.
- 错误对用户说明可执行的恢复方式; 原始异常仅输出到开发日志. 不把软件环境限制伪装为代码保证.

## 格式、注释与验证

采用 UTF-8、LF、两个空格缩进; Prettier 为格式权威, 手写代码上限 160 列.
遵循仓库当前的中文维护注释阶段, 注释使用 ASCII 标点; 发布准备时按根规范审查英文 API 注释.
生产函数提供简短的声明级契约注释, 重点说明所有权、前置条件、状态转换和失败路径, 不重复代码字面含义.

测试使用 Node.js 内置 `node:test` 和 `node:assert/strict`. 测试直接导入生产 TypeScript 模块;
帧调度通过假时钟验证, 几何与拾取使用真实 Three.js 数学实现, GPU 着色器仍需浏览器验证.
修复行为问题时补对应回归用例, 避免为样式或简单静态文案编写实现镜像测试.
不要将固定帧数截图当作性能承诺; 性能记录应包含分辨率、DPR、GPU renderer、刷新率和运行场景.

## 合并前检查

- 完整 `pnpm check` 通过, 改动涉及的浏览器交互通过.
- 运行时不导入演示数据, 没有多余帧循环或未释放资源.
- UI 数据来源和限制准确, 无假实时状态、隐式后端操作或未经授权的依赖变更.
- 包清单与锁文件一致, 构建产物、缓存、环境变量和密钥未纳入源码.
- 文档与实际实现一致. 本地整理不自动提交、推送、发布或变更仓库分支.
