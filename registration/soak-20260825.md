# Registration/Selector Two-Hour Endurance Qualification

> Historical evidence: this run predates the Client-level Registration
> coordinator and the one-listener/one-temporary-task Selector design. It remains
> valid protocol and fault history, but no longer qualifies current worker
> ownership. See
> [`concurrency-review-20260826.md`](concurrency-review-20260826.md).

This report preserves the earlier raw-core qualification. The later direct
typed API campaign is the current operational evidence and is documented in
[`typed-soak-20260825.md`](typed-soak-20260825.md):
7,608.409 Redis seconds, 4,000,000 typed Updates, transactional `One`/`Any`
traffic, and the complete post-soak Sentinel matrix.

## 1. Outcome

The current Registration/Selector implementation passed a fault-injected
endurance qualification against authenticated Redis Open Source 8.8.0.

- Redis server elapsed time: **7,263.649 seconds**.
- Qualification floor: **7,200 seconds**.
- Continuously live Registrations: **500**.
- Selectors: **8**, plus dedicated expiry and churn observers.
- Content Updates: **3,750,000**.
- Planned Go update-clock duration: **7,499.999 seconds**.
- Fault injections: **34/34 passed**.
- Unexpected asynchronous errors: **0**.
- Final Redis database size: **0**.
- Post-soak Lua, Rust, and Sentinel matrices: **PASS**.

This is qualification evidence, not a latency or availability SLO. It covers
one Redis 8.8 host, one LAN path, and the exact source fingerprint recorded in
the result. It does not qualify TLS, managed Redis, every Redis 8 minor, or an
Internet partition.

## 2. Exact source and environment

The final run compiled from an isolated copy of the working tree so concurrent
Catalog work could not alter a running test binary. Before the run, the 32
Registration/Selector, shared runtime, Lua, dependency, and soak-harness files
matched the working tree byte for byte:

```text
f0b26208d124faed7e0166c521bb45fd178e0bf7c698702f892160d1becd4e99
```

After the run, the working tree and isolated copy again matched. The only later
change in that fingerprint scope was the report-only fix that accepts an
absolute Sentinel result path outside the isolated copy. Product SDK and Lua
sources remained identical to the tested fingerprint.

Environment:

- Redis image: `redis:8.8.0`;
- Redis persistence: AOF, `appendfsync everysec`, on a run-owned bind directory;
- Redis host: `192.168.0.90`;
- client runtime: WSL2 Linux Go;
- Selector fan-out: 8;
- Registration TTL: 30 seconds;
- automatic content-preserving refresh: 10 seconds;
- Redis sampling interval: 30 seconds; and
- generated random ACL password and exact run-owned container/directory labels.

The harness never uses `FLUSHDB` or `FLUSHALL`. Cleanup validates the exact run
labels and owner marker before removing only its container and bind directory.

## 3. Workload and lifecycle coverage

Five hundred Registration writers are staggered evenly across each second.
Every writer changes one `Data` field once per Go scheduling second. Eight
Selectors independently converge on the same Type.

Two parallel lifecycle loops run throughout the update load:

1. Natural expiry registers 128 short-TTL records without graceful cleanup,
   proves they leave the active view, enter the bounded retained view, and are
   removed after the second TTL.
2. Churn registers 16 records, applies revision 2, explicitly unregisters them,
   and proves explicit deletion never enters retained state.

Final coverage:

| Lifecycle measurement | Result |
| --- | ---: |
| Natural-expiry cycles | 25 |
| Naturally expired Registrations | 3,200 |
| Peak retained records | 34 |
| Register/Update/Unregister cycles | 25 |
| Explicitly unregistered Registrations | 400 |
| Final content revision | 7,501 |
| Highest Selector generation | 15 |

Every Selector ended with exactly 500 records at revision 7,501 and the final
`Data.load` value. Closing all writers then converged every active and retained
view to empty before the fixture was removed.

## 7. Cross-clock qualification gate

An earlier otherwise successful run exposed a test-infrastructure defect: WSL
reported 7,201.7 seconds while the Redis host and Windows orchestrator measured
only 6,990.2 seconds. That run was rejected as the authoritative two-hour
result and retained only as diagnostic evidence.

The corrected harness records Redis `TIME` in every sample and requires an
independent Redis-server duration floor. The final run scheduled 7,500 Go
seconds to absorb virtualization drift and required at least 7,200 Redis
seconds. It measured 7,263.649 Redis seconds, so the two-hour claim no longer
depends on the WSL clock.

## 9. Assessment

Current Registration/Selector engineering score: **9.7/10**.

Registration Lua accepted-contract implementation score: **10/10**.

Registration Lua production-evidence confidence: **9.9/10**.

Strengths:

- atomic lifecycle mutations and readable string protocol results;
- SDK-owned validation with Lua restricted to Redis-state-dependent glue;
- exact 500-writer cadence, eight-way fan-out, natural expiry, retained state,
  explicit deletion, connection loss, cache loss, restart, and failover in one
  sustained run;
- independent Redis-server duration proof;
- exact final convergence, empty database, and goroutine return to baseline;
- deterministic Lua generation and byte-identical Go/Rust copies; and
- machine-readable raw samples and fault events.

Weaknesses and remaining evidence gaps:

- Redis Pub/Sub remains non-durable; gaps require repair or a new generation;
- pause/restart maxima reach seconds even though p99 remains milliseconds;
- a pause can temporarily grow the Redis connection pool above 250 clients;
- immutable O(N) Selector view publication remains allocation-sensitive at
  larger populations or higher content-change rates;
- application-owned Go and Rust Attr/Data codecs still need byte-exact
  cross-language vectors for each real consumer schema;
- only Redis 8.8, one LAN host, and eight Selectors received this endurance run;
  TLS, managed Redis, WAN partitions, sustained maximum payloads, more Redis 8
  minors, larger subscriber fan-out, multi-day operation, and deliberate Redis
  clock steps remain unqualified; and
- Sentinel asynchronous replication can lose an acknowledged write. The live
  owner repairs state, but this is not consensus or durable history.

The evidence justifies 9.9 rather than 10.0 production confidence: the accepted
Lua responsibility is complete, but the deployment matrix is not exhaustive.
